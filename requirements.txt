# Prism GUI runs on TOP of prism_terminal's engine (core_bridge.py puts
# prism_terminal/ on sys.path), so everything the engine imports has to be
# listed HERE as well — this file is the whole install set for a build, and
# .github/workflows/build.yml installs no other. The engine's own
# requirements.txt is for running the CLI standalone; the two drifting apart
# is what shipped a packaged app with no ezdxf and no Pillow. Anything the GUI
# can reach through core_bridge belongs in both.
#
# (prism_terminal's rich/questionary are the exception: they draw the CLI's
# terminal UI, which the GUI never calls into.)

# ── Desktop UI ─────────────────────────────────────────────────
PySide6>=6.5.0

# ── Shared engine deps (same as prism_terminal) ─────────────────
setuptools
packaging
requests
undetected-chromedriver
selenium>=4.0.0
pypdf
python-docx

# packaging/rthook_ssl_certs.py depends on this directly — requests pulls it
# in transitively too, but the packaged app needs it even where requests
# wouldn't otherwise force the version CI resolves, so it's explicit here.
certifi

# Prism Studio films a real web page rather than drawing from a template, so
# it needs an actual browser engine. `pip install` alone only gets the Python
# driver — the Chromium binary itself is a separate `playwright install
# chromium` step, which .github/workflows/build.yml runs (with
# PLAYWRIGHT_BROWSERS_PATH=0, so the browser lands INSIDE the package where
# packaging/prism.spec's collect_data_files can find it, rather than in the
# OS cache dir a frozen build can't reach into) right after this file installs.
#
# Not optional for a BUILD, same reasoning as imageio-ffmpeg below: a build
# without this ships a Studio button that falls back to Prism Reel on every
# customer machine instead of just this build machine. Adds roughly 250-400MB
# to the installer (the Node driver alone is ~130MB before Chromium).
playwright

# ── Add-ons we sell ─────────────────────────────────────────────────────────
# Not optional for a BUILD, however optional they are at runtime: PyInstaller
# can only bundle what is installed, so a packaging runner without these
# produces an app whose BOQ and Reel buttons fail on a customer's machine.
# packaging/prism.spec keeps numpy and PIL out of its excludes for the same
# reason; both halves are needed, and only one of them used to be here.
ezdxf     # BOQ reads DXF geometry directly (pulls in numpy)
pillow    # Prism Reel draws every frame with PIL

# Gerber, and the exact drift this file's header warns about happening again.
# Both were in prism_terminal/requirements.txt (or in neither) and not here,
# so no build has ever shipped them.
#
# shapely is the one that matters, because core/gerber.py degrades SILENTLY
# without it: `if not HAVE_SHAPELY` returns "not measured" for copper
# spacing, pitch and SMT pads. No error, no crash — a Gerber report with
# holes in it, from the most expensive add-on on the price book, on every
# packaged copy ever built. Found on the first Windows CI run of the suite,
# as 23 test failures nobody had seen.
#
# gerbonara reads and writes the Gerber itself (core/gerber_clean.py). It at
# least says so — "Cleaning needs the gerbonara package" — which is why it
# was less urgent and equally absent.
shapely
gerbonara

# FFmpeg, as a wheel. Pillow draws the frames and this encodes them.
#
# Not optional for a BUILD, and this is why: Windows does not come with
# FFmpeg and nobody installs it by accident, so the first Windows customer
# opened Reel and was handed a codec install guide instead of a video. macOS
# developers never see it because Homebrew put it there years ago.
#
# ~21-31 MB depending on platform, and PyInstaller only bundles the one it is
# building for. Prism runs it as a separate program rather than linking to it,
# so its licence travels beside the binary — see core/ffmpeg.py.
imageio-ffmpeg

# Inbox to Order reads the customer's own rate list, and a rate list is an
# Excel file — asking a factory owner to "save as CSV first" before Prism can
# quote anything is exactly the friction that stops it being used. Optional at
# RUNTIME (core/quoting.py falls back to CSV with an instruction if this is
# missing), but bundled in every build so nobody meets that fallback.
openpyxl

# ── Licensing ───────────────────────────────────────────────────────────────
# Ed25519 to verify licence tokens and authorisation leases, ChaCha20-Poly1305
# to decrypt the engine payload. Chosen over PyNaCl because PyInstaller ships
# maintained hooks for it, where PyNaCl's cffi _sodium extension is exactly
# the kind of thing that imports cleanly in development and dies in a frozen
# build.
cryptography

# The OS credential store (Keychain / Credential Manager / Secret Service),
# for the one reusable credential in the system: the licence key, which Prism
# keeps so it can silently re-activate a seat somebody released by mistake.
#
# DELIBERATELY OPTIONAL, and licensing/secretstore.py must keep working
# without it. A headless Linux box has no Secret Service, a locked keyring
# raises on first use, and neither may stop Prism starting — the fallback is
# the plaintext file the previous version used unconditionally, which is no
# worse than before and is reported honestly in diagnostics.
#
# Uncomment to build with it. Recommended for release builds on Windows and
# macOS, where a working backend is always present.
# keyring

# ── Voice input & wake word — needs PortAudio on the system first:
#   macOS:  brew install portaudio
#   Linux:  sudo apt install portaudio19-dev
# then:
pyaudio

# ── Mail-server discovery (optional, strongly recommended)
# Lets setup find the IMAP server from the domain's MX record. Without it,
# Prism can only guess imap./mail./<their-domain> — which works for a company
# running its own mail, and cannot work for anyone hosted on GoDaddy, Google
# Workspace, Microsoft 365 or Zoho. That is most small manufacturers, and the
# symptom is "the mail server didn't answer" on a perfectly good mailbox.
#
# core/inbox.py imports it defensively and falls back to guessing when absent,
# so leaving it out degrades setup rather than breaking the build.
dnspython
