## The problem in one paragraph

Right now anyone can download Prism from Releases and use it forever, free. We
want to hand a build to a named client and know that **it does nothing without a
key we personally issued**, and that a trial **stops on the day we said**. That
needs a server we host, because the customer's own computer cannot be trusted to
remember honestly when their trial started.

---

## The rule

> **No key, no Prism.** There is no free tier, no self-signup, no anonymous
> trial. Every single install — evaluation or paid — runs on a key that we
> generated by hand for that customer.

A "trial" isn't a separate mode. It's just a key with a short life:

| We issue | They get |
|---|---|
| `days: 10` | Ten days. Ends on day ten. |
| `days: 30, features: [core, boq]` | A month, BOQ unlocked, Email locked |
| `days: 365, seats: 5` | A year on five machines |

Same key format, same machinery, one number different.

### On day 10, what exactly happens?

The app **still opens**. History still readable, past outputs still there,
Setup still works. Only *new runs and add-ons* stop, with a clear message and
your contact details.

This matters: never hold a customer's own work hostage. A client locked out of
the BOQ output they produced last week won't buy — they'll be angry, and they'll
be right.

**Trials get zero grace days.** Paid licences get 3 days of slack to absorb a
late bank transfer. A trial you said was 10 days ends at 10 days, because that's
the date you put in the email.

## How the app knows what's unlocked

Two mechanisms, working together. The second is what makes this hard to defeat.

### Mechanism 1 — the passport

The server gives the app a **licence token**: a small block of text saying
*"this machine, this customer, these add-ons, valid until this date"*, carrying a
**digital signature**.

```
  ┌─────────────────────────────────────────────────────┐
  │  customer: RS Infotech                              │
  │  unlocks:  core, boq                                │
  │  machine:  a3f9c2…                                  │
  │  expires:  14 August 2026                           │
  ├─────────────────────────────────────────────────────┤
  │  signature: (only our server can produce this)      │
  └─────────────────────────────────────────────────────┘
```

Think of it as a **passport**. The customer holds it and can read it. They
cannot alter it — change one character and the signature stops matching. Only
our server holds the key that can produce a valid one.

It's valid for 7 days and renews silently in the background. That's why the app
keeps working on a construction site with no signal, and why our server going
down doesn't stop anybody.

### Mechanism 2 — the app ships incomplete

Here's the part that matters.

Prism's actual value isn't the window. It's a body of accumulated knowledge:
which AI tool is good at what, three carefully engineered prompt templates, and
— most laboriously — the **CSS selectors** that tell the automation where to
click and type inside Claude, ChatGPT, Kimi and the rest.

**None of that ships inside the build.** It arrives from our server when the
customer activates, encrypted so that only a valid passport can unlock it.

```
   What you download          What arrives on activation
   ┌──────────────────┐       ┌───────────────────────────┐
   │ The window       │       │ Tool knowledge            │
   │ The pipeline     │   +   │ Prompt templates          │  = a working Prism
   │ The file handling│       │ Where to click in Claude  │
   └──────────────────┘       └───────────────────────────┘
     a shell, on its own        the brain
```

So if someone strips the licence check out of the app, they get a shell that
opens, routes nothing, and drives no browser. **There's no lock to pick, because
the valuable part was never delivered.**

### And it goes stale by itself

Those CSS selectors break constantly — Claude and ChatGPT change their pages
without telling anyone. Keeping them working is permanent maintenance on our
side, and every customer gets the fixes automatically with each renewal.

A cracked copy stops renewing. So it slowly rots: this tool breaks, then that
one, until it's useless — **with no action from us at all**. A crack doesn't
produce a free copy of Prism. It produces a copy with an expiry date set by
Anthropic and OpenAI.

The same machinery is a real operational win regardless of licensing: **when a
selector breaks, we fix it on the server and every customer works again within
hours.** No new build, no release, nobody re-downloading anything. Today that
same fix means shipping four platform builds and chasing every client to update.

## So — is it foolproof?

Straight answer, because it shapes what we spend.

| Someone tries… | Result |
|---|---|
| Using it with no key at all | **Nothing works.** Activation screen only. |
| Editing the licence file to add add-ons | **Blocked.** Signature stops matching. |
| Setting the clock back to extend a trial | **Blocked.** The app remembers the latest date it's seen. |
| Deleting `~/.prism` to start over | **Blocked.** No key, no product. |
| Copying one licence to 10 machines | **Blocked.** Seats counted server-side. |
| Sharing the installer with another firm | **Blocked.** It's an empty shell without a key. |
| Taking a legit trial, patching the app, keeping the brain | **Works — but rots within weeks** as selectors break. |

That last row is the one honest gap, and closing it completely means moving the
routing onto our servers. That's real, it's specified in
[`06-tier-3-future.md`](06-tier-3-future.md), and we've deliberately deferred it
— it would mean every run needs internet and customer data would transit our
infrastructure, which some engineering clients simply won't accept.

For handing a build to a named client on a 10-day evaluation, what's described
here is enough. The person who'd reverse-engineer a compiled app is not the
person running quantity takeoffs at a construction firm.

## What we're building

**A server** (small — one Python service and a database, roughly ₹1,500–2,000
a month):
- an admin panel where we issue keys, set the day count, and pick add-ons
- signs passports
- counts seats
- serves the encrypted brain payload
- lets us extend anyone's trial instantly, without a new build

**Changes inside the Prism app:**
- an activation screen on first launch
- a check at startup and when opening each add-on
- locked add-ons show an upgrade message instead of opening
- the tool knowledge and prompts move out of the bundle and arrive on activation
- a Licence section in Setup: plan, seats used, expiry, deactivate this device

## Glossary

| Term | Meaning |
|---|---|
| **Licence key** | What the customer types in, once. `PRSM-XXXXX-XXXXX-XXXXX-XXXXX`. We generate it by hand. |
| **Token / passport** | What the app stores and checks on every launch. Signed, 7-day life, renews itself. The customer never sees it. |
| **Payload / brain** | The tool knowledge, prompts and selectors that arrive on activation instead of shipping in the build. |
| **Entitlement / feature** | One unlockable thing: `core`, `boq`, `email`, `reel`, `bom`. |
| **Seat** | One activated machine. A 5-seat licence runs on 5 computers. |
| **Device fingerprint** | A one-way hash of a machine's hardware ID. Counts seats without collecting anything identifying. |
| **Grace period** | 3 extra days after expiry, for paid licences only. Trials get none. |
| **Activation** | Turning a key into a passport on one machine. Uses one seat. |
| **Deactivation** | Releasing a seat so the customer can move to a new machine. |
