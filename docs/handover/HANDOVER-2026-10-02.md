What was released, what was fixed afterwards, how it was checked, and what is
still open. Written so the next person (or agent) can pick it up cold.

## 1. Release 1.6.0 — shipped

- Tag `v1.6.0` on `7dbdb0c` (engine `04d326f`). Signed for **Windows, Linux and
  macOS**; each signed manifest verifies with key `u1`, and every update file is
  on `v1.6.0-assets-<platform>` (Windows 909/909, Linux 991/991, macOS 984/984).
- A 1.5.8 install can update straight to 1.6.0 in the app once Render's
  `LATEST_CLIENT_VERSION` says `1.6.0` (the lease already lists it).
- It went out with 17 Linux tests red (also red on `main` beforehand). All of
  them are fixed below; the tag itself is unchanged.
- `devtools/release_all.py` now releases **Windows, Linux, macOS** in that
  order and takes `--only <platform>`.
- The signing key was pasted into a chat during the release and used from a
  temporary file that was shredded. **Rotate it.**

### Tests

Every red test from CI and from a full local run was a test or isolation problem
except the product bugs listed above. The recurring cause: code that falls back
to the developer's **real** `~/.prism/runs` (`dashboard_data._run_files`,
`workspace.runs_dir`) — it hung the suite at ~24% and made `test_roles` fail on
any machine that had used Prism. Those tests now redirect it. A single-process
full run is very slow on a 7.5 GB machine (swap); run it as separate processes
(8 chunks of ~20 files worked).

## 4. Still open

   changes and rewrites the whole file with no lock and a fixed `<path>.tmp`.
   A lock file is simple but unreliable on the shared/network drives this feature
   is for; a central store is the robust fix and a bigger change. Atomic replace
   alone does not solve lost updates.
2. **Finding 2 needs a Render deploy** of `license_server`, and a look at the
   Leads usage rows afterwards.

## 5. Traps worth knowing

- `pkill -f <pattern>` inside a tool call kills the call's own shell if the
  pattern text is anywhere in that command line; use `[p]attern` and a separate call.
- A Codex session may be running pytest in the same repo; two concurrent suites
  starve the machine.
- Never delete `devtools/.last_signed_update_version*` (signing rollback state).
- Do not run the suite with a Prism instance up on the real `~/.prism`.
